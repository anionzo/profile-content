Ngày thường mình viết phần mềm nhà trường. Portfolio thì khác: không có phiên đăng nhập nghiệp vụ, không có bảy trăm người thi cùng lúc. Chỉ cần chữ, ảnh, và vài trang đứng yên.

Mình từng nhét tất cả vào một kho giao diện. Câu dưới tên nằm trong component. Sửa tiểu sử là đụng code. Sau một thời gian mình thấy mình đang dùng framework ứng dụng cho một việc vốn là xuất bản.

Astro cộng một kho chữ giải quyết đúng chỗ đó. Không phải vì Astro đang hot, mà vì nó in ra HTML và chịu để mình giữ chữ ở một nơi khác.

## Việc mình cần, không phải việc framework khoe

Vài trang đứng yên: giới thiệu, kinh nghiệm, dự án, blog. JSON cho hồ sơ. Markdown cho bài. Ảnh và một file CV.

Không cần đổi trang kiểu ứng dụng chỉ để đổi theme. Theme là class trên thẻ gốc. Không cần gọi API lúc người ta đọc, dựng xong là HTML tĩnh.

Component của Astro gần với HTML. Phần còn lại mình tự viết: khuôn dữ liệu, script đồng bộ, vài việc khi đẩy lên.

## Tuần đó làm gì, từng cụm ngày

Ngày một và hai: tạo kho chữ. File JSON cho hồ sơ, việc làm, học vấn, dự án. Bài viết đặt tên theo ngày và slug. Một field trạng thái: nháp hoặc ra. Ảnh đi đường public, không đi đường bí ẩn trong máy mình.

Ngày ba: viết khuôn. Thiếu tiêu đề, ngày kết thúc sai kiểu, hay slug trên tên file không khớp phần đầu bài là build chết ngay. Fail sớm rẻ hơn fail khi trang đã lên.

Ngày bốn và năm: script đồng bộ. Máy mình Windows, lệnh copy kiểu Unix không có. Script Node tìm kho chữ cạnh kho site, copy bài, copy ảnh, copy CV. Quên bước ảnh thì ảnh đại diện trống. Mình đã dính một lần, ngồi nhìn khung trống khá lâu trước khi hiểu.

![Cột đá và nắng trên trang chủ](/images/posts/hoc-astro/screenshot-1.png)

Ngày sáu và bảy: RSS, sơ đồ trang, ảnh khi gửi link, và lọc nháp. Bài nháp không có đường trên bản public. Muốn xem thì chạy máy mình.

## Chỗ mình suýt làm sai

Submodule và file ignore đánh nhau. Ignore nhầm đường thì máy dựng không thấy chữ. Local mình để hai thư mục cạnh nhau là đủ.

Script đồng bộ viết kiểu Unix trước. Viết lại bằng API của Node thì hết chuyện trên Windows.

Lúc dựng trang, đường đọc file bám theo URL của module. Sau khi đóng gói, URL đó trỏ vào chỗ không còn file JSON. Đổi sang thư mục đang chạy thì mới ra.

Không chuyện nào trong đó là lỗi của Astro, chỉ là mình mang thói quen làm app vào một việc vốn là in giấy.

## Việc mình không nhờ Astro làm

Mình không viết lại hệ thống trường bằng Astro, cũng không có ý thay công việc ban ngày. Thứ Astro thay là cái thói quen nhét tiểu sử vào file giao diện.

Chữ có khuôn, site chỉ việc đọc, kiểm tra rồi in. Bạn đọc được bài này nghĩa là bước in đã xong, còn bước giữ cho đúng thì nằm ở kho chữ, không nằm ở framework.

Weekdays I write university software. A portfolio is different: no business login session, no seven hundred people in an exam. Only copy, images, and a few still pages.

I once stuffed everything into one UI repo. The tagline lived in a component. Editing a bio meant touching code. After a while I saw I was using an application framework for what is basically publishing.

Astro plus a content repo fixes exactly that. Not because Astro is hot, but because it prints HTML and lets me keep the copy somewhere else.

## What I needed, not what frameworks pitch

A few still pages: about, experience, projects, blog. JSON for the profile. Markdown for posts. Images and one CV file.

No app-style routing just to change theme. Theme is a class on the root. No API call while someone reads, the build just finishes as static HTML.

Astro components sit close to HTML. The rest I wrote myself: data shape, sync script, a few ship steps.

## What that week looked like

Days one and two: content repo. JSON for profile, work, school, projects. Posts named by date and slug. A status field: draft or published. Images on a public path, not a private mystery on my machine.

Day three: schema. A missing title, a bad end date, or a file slug that does not match the frontmatter kills the build right away. Failing early is cheaper than failing live.

Days four and five: sync script. My machine is Windows; Unix copy tricks are missing. A Node script finds the sibling content folder, copies posts, images, CV. Skip images and the avatar is empty. I hit that once and stared at a blank frame longer than I should have.

![Stone columns and sun on the home page](/images/posts/hoc-astro/screenshot-1.png)

Days six and seven: RSS, sitemap, share image, draft filter. Drafts have no public path. To preview, run locally.

## Where I almost went wrong

Submodules fighting ignore rules. Ignore the wrong path and the build machine sees no copy. Locally two folders side by side is enough.

Sync script first written the Unix way. Rewritten on Node APIs and Windows stopped being a special case.

At build time file reads followed the module URL. After bundle that URL no longer pointed at JSON. Switching to the process working directory fixed it.

None of that was Astro's fault, it was me bringing app habits into what is basically printing paper.

## What I did not ask Astro to do

I did not rewrite the school systems in Astro, and I did not replace the day job. What Astro replaced was the habit of burying a bio in a UI file.

Copy has a shape, and the site only reads, checks, and prints it. If you can read this, the print step worked, and keeping it true lives in the content repo rather than in the framework.
